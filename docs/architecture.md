# RK3568 模块架构与现状

更新时间：2026-10-15（按最新统一界面、NPU、语音和 MQTT 验收同步）

## 状态标签

- **已确认实现**：已有实现，且已完成文档记录的构建、部署、冒烟或真实运行验证。
- **存在代码但尚未现场验收**：实现或部署已完成，但当前任务仍要求在真实板屏或真实场景完成验收。
- **规划中/未实现**：仅有方向、目录入口或设计意图，不代表已有可运行功能。

## 当前模块关系

```text
板载麦克风/扬声器
        │
        ▼
中文 KWS / VAD → Voice Python 服务 ── AF_UNIX ── Qt 统一“智能终端”
        │             │                        ├── 常驻语音区 / 任务状态
        │             ├── MiMo ASR / V2.6 Flash / TTS
        │             ├── 离线固定指令 / 时间、天气
        │             └── 受控 Action → 应用 START/STOP 入口
        │                                      │
        └── 按键备用；独立 aivoice 仍保留         │
                                               ▼
USB UVC Camera → Qt 同帧预览 → YOLOv8n INT8 NPU → 有界跟踪控制
                            TFLite CPU 手掌模式保留       │
                                                         ▼
RK3568 /dev/ttyS9 ── UART9 M1 / USART1 ── STM32F103C8T6
                                             ├── PC13 LED（已现场验证）
                                             └── 双轴 MG90S（人物/手掌模式）

ConnMan ── ConnmanWifiController ── Settings / 桌面内 Wi-Fi 状态条

手机网页 ←── EMQX TLS/WSS ── 独立板端只读状态代理（手动运行）
   ↑ 电脑 HTTP 提供网页；不接入 UART 控制或相机视频
VM Mosquitto / 板端 pub-sub 基础成果保留
```

## Voice

### 已确认实现

- 当前联网语音链路已覆盖录音、MiMo ASR/LLM/TTS 与 ALSA 播放；历史百度 ASR、火山 TTS 接入不再代表当前部署链路。
- 正式 LLM 为 `mimo-v2.6-flash`（关闭 thinking、流式回复），ASR/TTS 保持 v2.5。中文 sherpa KWS“小爱同学”、Silero VAD 自动收音、本地提示和按键备用已有部署/基础实测，离线使用 Vosk 固定指令，不部署本地 LLM。
- 联网语音经白名单 Action、UART 回执及状态回读控制 STM32 PC13，用户已目视确认亮灭。
- 无 TTY 服务通过 `/tmp/ai-voice.sock` 提供 `status`、`start`、`stop`、`cancel`，并支持单轮互斥、客户端重连与状态事件。
- Qt aivoice 已通过 `QLocalSocket` 显示语音状态、识别文本、流式回答与诊断信息。
- 黑色统一界面复用同一 VoiceBridge 和服务，不需要切到独立 aivoice；受控人物启停调用应用入口，由现有 worker 管理 UART。固定指令与普通对话分流，LLM 不生成原始串口命令。
- 16 kHz 音频约束、录音异常恢复、临时文件清理、播放超时与短周期恢复已完成验证。
- 普通对话走流式路径，显式时间/天气意图走工具路径。离线固定语音已达阶段展示可用：语音任务 2026-09-26 覆盖 Wi-Fi 在线但无互联网，4 轮灯控约 0.6–0.8 秒完成回读，1 轮未匹配未动作，恢复联网后对话正常。

### 存在代码但尚未现场验收

- 离线固定语音仍有偶发拒识，其他网络故障下的降级与长期重复性未完全覆盖；已有快速降级场景不必重复推倒验证。
- 已有 V2.6 真对话首正文 6950 ms、录音结束至首播 9982 ms 的一次记录，不宣称升级提速。统一版真实语音与检测并行、语音 STOP 仍待补验，漏/误唤醒与长稳未全部量化。

### 规划中/未实现

- 风扇噪声/麦克风优化按用户要求暂缓；连续对话增强不是第一版必做项。不得将这些待优化项写成唤醒或语音跟踪仍未实现。

## Qt UI

### 已确认实现

- `aivoice` Qt Quick 应用、桌面图标、SystemUI 生命周期接入、AArch64 构建和板端启动均已验证。
- 语音 UI 与 Python 服务的 Socket 协议已在真实启动周期中使用。
- `gimbal-joystick` 已有独立“云台摄像”桌面入口、实时画面、双轴摇杆、手掌跟踪/回中位/停止状态与退出。Qt 同一摄像头帧交给检测进程，不开第二套摄像头采集。2026-09-30 已获板屏现场反馈，最新边界见 [当前交接](../HANDOFF.md)。
- 2026-10-14 正式入口已换成黑色统一“智能终端”：人物框与选人、常驻语音/回复/执行状态、可展开手动控制和独立停止。同一窗口内切换面板不销毁检测任务；用户确认退出后重开正常。见 [统一界面说明](../apps/qt-ui/gimbal-joystick/UNIFIED_UI.md)。
- 真正失焦、隐藏、相机故障或退出仍停止检测/跟随；退出释放资源，不提供退出后后台跟随。独立 aivoice 仍保留，不应为并行操作再开第二套相机应用。

### 存在代码但尚未现场验收

- 统一版普通问答与 NPU 检测重叠运行、语音停止需实际补验，桌面 Qt6 mock 和板端 Qt5 构建不能代替。当前不能开板，不在本轮重复部署或声称通过。

### 规划中/未实现

- 后续体验优化基于当前统一界面增量推进，不重新建立整套 HMI。

## MQTT

### 已确认实现

- Ubuntu VM 上的 Mosquitto Broker 与板端 MQTT pub/sub 已完成基础连通验证。
- EMQX Serverless 独立设备/手机账号与精确主题 ACL 已配置，手机 `get_status` 返回真实板端 Linux 采样。两个账号登录、8 项 ACL 负例、重复/过期请求、正常退出/遗嘱/重连和网页状态过期/恢复已联调；iPhone 结果由用户确认。
- 独立代理在 `/opt/rk3568-mqtt-status-20261013/`，私有 Paho 2.1.0/CA，不升级系统库。电脑提供网页与手动启动工具，无常驻自启动；原 echo 配置保留。入口 [MQTT README](../apps/mqtt-cloud/README.md)，证据 `local/mqtt/live-20261014/REPORT.md`。

### 存在代码但尚未现场验收

- 本次只读业务已验收；后续运行仍需确认现场地址并手动启动。没有板端时不重复联网验收，离线测试不代表当前设备在线。

### 规划中/未实现

- 公网网页、视频、远程跟随/云台动作和语音 MQTT 工具尚未实现，不属于第一版必做项。MQTT 不参与 UART 实时控制路径。

## UART、STM32 与 Vision

### 已确认实现

- STM32F103C8T6 USART1 固件和 RK3568 UART9 M1 `/dev/ttyS9` 已完成 115200、8N1、无流控的现场连通；UART9 boot 持久化并经热重启、断电冷启动验证。
- ASCII `PING`/`PONG`、PC13 `LED ON`/`LED OFF`、`LED?` 状态回读及实物亮灭已有记录；二进制 CRC 仍只是草案。见 [HANDOFF](../HANDOFF.md)、[STM32 README](../stm32/README.md) 与 [UART 文档](uart-protocol-draft.md)。
- UVC 摄像头已完成 USB 枚举、1080p MJPEG/640×480 YUYV 取流、样帧与屏幕预览，证据在 `local/uvc-acceptance-20260928/`。
- STM32 已支持 PAN/TILT/TRK、双轴 PWM、限幅与 2 秒失联停止；手掌跟踪原型已部署。最新固件停止后保留最后输出脉宽，重启后 `TRK POS?` 为未知，显式回中位后才允许跟踪；参数与构建记录见 `apps/qt-ui/gimbal-joystick/README.md`、`local/gimbal-resume-fix-20260930.md`。
- 正式人物入口为 YOLOv8n INT8 `rknn-v8`，匹配 RKNN Runtime 1.5.2 / driver 0.9.2；MediaPipe 来源的 CPU TFLite 手掌模式仍保留，两者不是同一检测模型。预览取流约 30 FPS，不等于人物检测约 7.5 Hz。
- 人物目标按当前框的几何关联恢复，运动样本保留 500 ms 帧龄门槛、歧义暂停、限位和停止；没有身份重识别。当前目标点为人体框中心，头部优先未实现，不能据置信度断言真人或活体。

### 已现场使用、仍待量化的部分

- 摄像头、双轴 MG90S 与外部供电已用于实验；Pan 500–2500 µs、Tilt 750–2250 µs 有动作观察记录。供电电压/电流、负载余量、实际机械角度与机械延迟未测，不能把供应商参数或 PWM 回读当作实测轴角。
- 手掌跟踪最新反馈为“效果还可以，后面可以继续优化”，有启动及延迟反馈修复记录，仍未达到精确同步跟随或整机长期稳定性验收。

### 规划中/未实现

- 头部定位/关键点可复用已有图像离线评估，低头漏检、最终停跟及多人/长期表现仍待改善。YOLO26n 已比较但收益不足，不自动替换或升级 Runtime。
- Qt 云台 worker 在整个应用运行期持有 UART9 文件锁；语音 PC13 或独立云台事务会返回 busy。语音启停跟踪需要受控的应用入口协调串口所有权、状态与回执，不能另开串口绕锁。
- 物理动作经过白名单、限幅和回执，LLM 不直接生成原始 UART 命令；阶段验收见 [模块推进路线](module-roadmap.md)。

- 源码版本和板端恢复分开：当前哈希及精确备份见 [HANDOFF](../HANDOFF.md)；`local/` 的权重、日志、部署备份和打印产物不随 Git clone 恢复。
