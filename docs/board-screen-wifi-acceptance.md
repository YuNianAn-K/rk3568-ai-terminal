# RK3568 Wi-Fi 板屏验收

更新时间：2026-09-06

## 1. 验收目标

本阶段只确认以下基础能力：

- RK3568 系统能够启动；
- 5.5 寸 MIPI 屏能正常显示；
- 触摸能响应；
- Wi-Fi 能扫描、连接并联网；
- 已部署的 Qt 程序能从系统桌面或应用入口启动；
- 可记录基础状态与问题现象。

当前已知事实是：Buildroot、MIPI 屏、系统级 Wi-Fi、Settings/SystemUI 和 `aivoice` 的构建与板端部署均有历史验证记录。右上角状态、扫描列表、密码连接、错误提示和重启回连仍未完成本次板屏人工验收。

## 2. 不属于本阶段的内容

本阶段不验证 STM32、UART、MQTT 业务、Vision、完整语音链路、自动启动或最终 UI。不要修改系统配置、自动连接 Wi-Fi、输入或记录 Wi-Fi 密码。

## 3. 用户在板子上手动执行的检查

### 系统启动

- 板子正常开机，屏幕亮起，能进入系统界面或终端；
- 通过当前实际 DHCP 地址确认 SSH 可连接；
- 切换热点后重新确认开发板与 VM 的地址，不使用历史地址。

### 屏幕与触摸

- MIPI 屏显示正常，无黑屏、花屏或明显闪烁；
- 打开系统 Settings，确认界面内容与分辨率可读；
- 点击 Wi-Fi 项目、SSID 和屏幕键盘，观察是否有响应、坐标偏移或触摸无响应；
- 如有异常，记录发生页面、操作步骤和屏幕现象；是否需要校准由实际系统判断。

### Wi-Fi

- 在系统“设置 → 无线局域网”确认能看到 SSID 列表、锁和信号图标；
- 在右上角确认 SystemUI 的当前 SSID 与信号显示；
- 准备一个可控热点，在板屏通过屏幕键盘输入密码并连接；密码不得写入命令行、日志或本文档；
- 观察错误密码提示与成功连接提示；
- 连接后确认 IP、网关和公网连通性；重启后确认是否自动回连。

### Qt 程序

- 从板端桌面图标或当前系统应用入口启动 `aivoice`；
- 记录实际使用的启动入口或命令。当前仓库只确认其已部署和启动过，不把未经现场确认的二进制路径写成固定命令；
- 检查是否显示、是否全屏适配 5.5 寸屏、是否能响应触摸、是否有卡死，以及能否正常退出。

## 4. 建议手动执行的命令

以下命令仅查看状态；不同 Buildroot 镜像可能命令不同，以实际系统为准。若没有 `iw`、`free` 或完整 `ps`，跳过并记录“命令不可用”。

```sh
pwd
uname -a
ip addr
ip route
iw dev
ping -c 4 <网关IP>
ping -c 4 8.8.8.8
ps aux | grep -i aivoice
ps aux | grep -i qt
df -h
free -h
dmesg | tail -n 50
```

`<网关IP>` 应从本次 `ip route` 输出中获取。不要把 Wi-Fi 密码传给命令或写进保存的终端输出。

## 6. 通过标准

本阶段通过需要满足：板子能稳定启动；MIPI 屏显示正常；触摸可用；Wi-Fi 能扫描、连接并联网；Qt 程序能启动并响应触摸；用户已记录实际启动入口与异常现象。错误密码提示和重启自动回连也需由板屏完成确认。

## 7. 不通过时的定位顺序

```text
电源
→ 系统启动
→ 屏幕显示
→ 触摸驱动或校准
→ Wi-Fi 驱动/ConnMan 配置
→ 网络连通性
→ Qt 环境与系统应用入口
→ Qt 程序本身
```

先记录最早失败的一层及证据，再决定是否进入源码排查；本轮不为排障修改系统或 Qt 代码。
