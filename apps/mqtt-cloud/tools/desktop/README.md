# 手动启动手机状态查询

此入口把已验证的网页服务与板端独立代理放在一个可见窗口里管理，支持启动、停止和重试。
不安装服务，不设置开机自启动，不修改云端 ACL、防火墙、网络、固件或其他应用。

## 这台电脑的入口

双击仓库内 `local/mqtt/manual/启动 MQTT 控制台.cmd`。

1. 确认板端 `wlan0` 当前 IPv4，在窗口填写；DHCP 地址不自动沿用。
2. 输入 `device-rk3568-01` 的 MQTT 密码，点击“启动”。不要输入控制台登录密码或手机密码。
3. 窗口显示“板端代理已连接”后，iPhone 与电脑连接同一可信热点，打开窗口下方手机网址。
4. Safari 选择“真实设备状态”，设备 ID `rk3568-01`、用户名 `phone-owner`，输入手机账号密码并连接、查询。
5. 用完点击窗口“停止”，等显示停止完成；关闭窗口也会请求正常停止本次会话。

电脑和窗口需保持运行。单次最长 8 小时，到期需重新启动；这不是无人值守服务。
窗口“已连接”表示初始云端连接已确认，不是连续在线监测；实时在线、过期和离线以手机网页为准。
请求仍只支持 `get_status`，视频、云台、摄像头和语音未接入。

## 运行与凭据

- 本机 Python、Node、SSH 路径在 Git 忽略的 `local/mqtt/manual/runtime.json`；不存在时先按实际安装位置填写。
- 使用仓库已有可信主机文件 `local/pan-ssh-known-hosts`，严格校验 SSH 公钥；当前 HostKeyAlias 是已验证的板端身份别名 `10.176.237.235`，不是连接目标地址。
- 连接目标始终来自用户现场填写的私有 IPv4；端口 8787 被占用时拒绝启动，不停止或接管其他网页。
- 板端必须是 `ATK-DLRK3568 / aarch64`，独立目录 `/opt/rk3568-mqtt-status-20261013/` 的代理、协议及 CA 哈希需匹配已验证版本。版本变化后先重新验证，不能删除检查强行启动。
- 若该目录已有代理运行，拒绝启动；板端 `/tmp/rk3568-mqtt-manual.lock` 是无凭据的互斥锁文件。
- 密码只通过进程 stdin 和加密 SSH stdin 传入代理环境，启动后清空输入框；不放在 argv、状态 JSON、网页服务日志或运行配置里。
- SSH 控制连接每 5 秒续租；控制连接长时间消失时，板端包装器约 40 秒后结束它自己启动的代理，避免失联常驻。板端系统/网络中断时仍须检查实际进程，不能只依据电脑状态宣称远程已停止。
- 日志、公开状态和本机路径均在 `local/mqtt/manual/`；只记录本次拥有的 PID、手机网址和状态文字，不含密码。
- 从 Codex 沙箱启动网页可能无法被手机访问；应通过正常审批启动，或用户直接双击本机入口。不得关闭沙箱或防火墙来绕过限制。

```powershell
# [Windows] 仓库根目录；只检查路径，不启动网络或代理
powershell.exe -NoProfile -File apps/mqtt-cloud/tools/desktop/start.ps1 -Check
# 使用本机 runtime.json 指定的 Python，运行资源隔离与失败路径检查
python -m unittest discover -s apps/mqtt-cloud/tests -p test_desktop_session.py -v
```

停止会话即可回退运行状态；本入口没有修改板端应用文件或安装系统依赖。保留已部署目录和原 echo 配置。
