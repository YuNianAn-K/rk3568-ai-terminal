## 控制方式

- 手指从圆盘中心移向左、右、上、下，只选择占优势的一轴；不做对角线联动。
- 底座左/右分别发送 `PAN +100` / `PAN -100`（1600 / 1400 µs）。
- 上轴后仰/前倾分别发送 `TILT -100` / `TILT +100`（1400 / 1600 µs）。
- 每次先发送 `PAN STOP`、对应轴 `CENTER`，等待 0.25 秒后输出目标。松手、
  换向、窗口隐藏或失焦、按下“立即停止”、退出应用均发送 `PAN STOP` 并核对双轴 `OFF`。
- 单次输出最多 1.2 秒；STM32 还有 2 秒失联停止保护。超过单次时限后，松手再触摸。
- 摄像头使用板端已验收的 UVC `2M` 设备，预览请求为 640×480、30 FPS；Qt 实际显示帧率尚未测量。拔出摄像头时显示断开、
  停止云台并禁用摇杆；重新插入后恢复预览。UART 工作进程异常时显示故障并禁用摇杆，
  若串口真的失联，最终停止仍依赖 STM32 自身的 2 秒保护，界面不声称已收到 OFF 回执。

## 受限跟手

点“开始跟手”才启动手部检测；摇杆在跟手期间禁用，立即停止与退出始终有效。
STM32 重启后位置未知，须先明确点“回中位”（约 1.2 秒后自动停止），再启用跟手。
停止只撤销 PWM，保留最后输出的脉宽；再次跟手从该脉宽继续，启动不再强制回到 1500 µs。
保留值只在 RAM 中，不跨断电保存，不是角度反馈；停机期间被外力转动的位置无法感知。
`TRK POS?` 只读返回最后输出的双轴脉宽或 `TRK_POS=UNKNOWN`；未知时 `TRK ARM` 拒绝动作。
`TRK CENTER` 是 UI 白名单中的显式回中位命令，已知位置时沿原有斜坡推进，未知时初始化到 1500 µs。
摄像头的同一帧通过 Qt `QVideoProbe` 交给检测进程，并绘制约 20 FPS 的预览；检测进程最多按约 10 FPS 取样，实际频率还受推理时间限制，不单独打开摄像头。
完整单只手的检测置信度至少 0.80，约 1.2 秒内三次有效识别后才向 STM32 发送 `TRK ARM`。
中心误差超过画面宽/高的 8% 时，最多每 0.10 秒对水平、俯仰分别修正；
将误差换算为相对取帧时脉宽的目标，避免对已移动的云台重复追加过期误差；
对绝对目标做轻度平滑。每轴每次最多调整三档 80 µs，目标最多领先当前 PWM 240 µs。
帧坐标携带单调时钟时间，控制侧以脉宽历史估计取帧位置；超过 500 ms 的旧帧触发停止。
估计仍不是实际轴角，不能补偿所有机械滞后。
STM32 每 20 ms 把实际 PWM 向目标推进最多 24 µs。跟手是根据画面误差持续对准，
没有舵机角度反馈，不能把手的屏幕坐标直接换成精确的机械角度，也不能消除摄像头、推理和舵机的物理延迟。
双轴 PWM 可同时输出。底座目标限于已验收的 500–2500 µs，上轴限于 750–2250 µs；
上轴曾短时观察到 600 µs 接近机械边缘，因此不纳入自动范围。这些脉宽不是实测角度。
手连续丢失超过 1.4 秒、出现第二只手后持续无法确认目标、视频停顿、UART 异常、摄像头拔出、按停止或退出时撤销跟手并请求两轴 OFF。
STM32 独立执行 2 秒失联停止。手部检测仅用于手掌中心，不推断具体手势或人物身份。

检测模型取自 Google MediaPipe 的 `palm_detection_lite.tflite`：
`https://storage.googleapis.com/mediapipe-assets/palm_detection_lite.tflite`；
SHA256 `E9A4AADDF90DDA56A87235303CF00E4C2D3FB28725F68FD88772997DAC905C18`。
板端使用现有 `cv2`、`numpy`、`tflite_runtime`，未增加系统包。

## 板端启动

安装在 `/opt/ui/gimbal-joystick/` 后，可在板屏应用列表点击“云台摄像”。
对应入口位于第二页 `/opt/ui/src/ATK-DLRK3568/apk2.cfg` 的“AI语音”后面，
应用通过桌面的 Qt Remote Objects 协议保持窗口激活并在退出时返回桌面。入口由
`/opt/ui/src/apps/gimbalcam` 调用本目录的 `start.sh`；启动锁防止重复占用摄像头和 UART。
也可在开发板 xterm 执行：

```sh
/opt/ui/gimbal-joystick/start.sh
```

退出请点应用右上角的“退出”；退出后释放 UART9 文件锁。应用不会开机自启。

## 延迟诊断

在开发板执行 `GIMBAL_TIMING=1 /opt/ui/gimbal-joystick/start.sh` 可启用计时日志，
默认关闭。日志前缀为 `GIMBAL_TIMING`，记录 Qt 收到帧至识别结果、模型预处理/
推理/后处理、控制进程等待、UART 回执、控制批次和停止确认。
诊断模式保留相同的动作参数、限幅和失联保护，不保存摄像头图片。
帧接收间隔不等于传感器至屏幕延迟；`PAN?`/`TILT?` 是当前 PWM 脉宽，
不是舵机实际角度。真实机械延迟需要另外的视频或角度反馈测量。
