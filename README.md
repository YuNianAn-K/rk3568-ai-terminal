# RK3568 AIoT 智能视觉交互终端

**基于嵌入式 Linux 与 STM32 的桌面多模态交互原型：听懂指令、感知人物、控制云台，并反馈执行结果。**

`RK3568` · `Buildroot Linux` · `Qt / QML` · `YOLOv8 / RKNN` · `STM32` · `MQTT`

本项目面向本科毕业设计与嵌入式 Linux 工程实践，将语音交互、端侧视觉推理、实时执行控制和远程状态查询整合到一套真实硬件中。RK3568 承担界面、视觉与应用调度，STM32 承担双轴 PWM 和执行保护；联网对话调用云端模型，断网时保留本地固定指令能力，不在板端部署大语言模型。

**当前阶段：核心链路已打通，正在优化正常使用场景下的人物跟随体验与整机集成。** 本仓库展示实际实现和验证记录，不将规划功能或离线回放结果写成已完成的整机能力。

## 核心功能

| 模块 | 已实现能力 | 当前边界 |
| --- | --- | --- |
| 语音交互 | 本地中文唤醒、VAD 自动收音、按键备用入口，MiMo ASR / LLM / TTS，流式回复与音频播放 | 风扇噪声、远场识别及完整交互延迟仍待优化 |
| 本地控制 | 离线固定指令；语音控制 PC13 灯，以及受控启动、停止人物跟随 | 不是离线通用对话模型，也不是任意自然语言执行器 |
| 人物视觉 | UVC 取流、YOLOv8n INT8 NPU 检测、目标选择、双轴跟随；CONT-V2 包含人脸／人体构图衔接 | 正常移动已有实测，快速运动、复杂遮挡与多人交叉仍需完善 |
| 实时执行 | STM32 USART1 通信、双轴 PWM、保留位置续接、渐进运动、停止与失联保护 | PWM 范围不等于实际机械角度；装配后须核对限位 |
| Qt 界面 | 相机预览、检测框、常驻语音区、执行状态、手动控制与独立停止 | 已部署统一界面；真实语音与检测并行的完整稳定性仍待补验 |
| MQTT 云端 | 手机网页经 EMQX 查询真实板端状态，包含请求关联、超时、遗嘱与主题权限隔离 | 已验证只读查询，不包含公网视频或远程机械控制；ECS 迁移仍在准备 |

典型使用流程：在触屏中检测并确认人物，通过语音或按钮请求开始跟随；系统检查相机、目标和执行状态后控制云台。操作结果返回界面，用户可随时通过独立停止入口结束运动。

## 系统架构

```text
麦克风 / 触屏                    云端 MiMo：ASR / LLM / TTS
      │                                      ▲
      ▼                                      │ HTTPS
┌────────────────── RK3568 / Buildroot Linux ─┴───────────────┐
│ Qt / QML 界面 ── 本地语音服务 ── 受控 Action 与执行回执       │
│ UVC 摄像头 ── RKNN 人物检测 ── 目标关联 / 构图 ── 跟随控制   │
│ MQTT 状态代理 ─────────────────────────────── 远程只读查询    │
└─────────────────────────┬──────────────────────────────────┘
                          │ UART9 ↔ USART1
                          ▼
                 STM32F103C8T6
           PWM / 渐进运动 / 限位 / 失联停止
                          │
                          ▼
                    双轴舵机云台
```

检测、语音与硬件执行通过明确接口协作。**LLM 不直接生成原始 UART 命令**；物理动作经过受控接口、状态检查和回执确认，停止路径不依赖普通问答完成。

## 工程实现亮点

- **Linux + MCU 分工：** Linux 负责复杂交互与感知，STM32 负责执行时序和底层保护，通过文本协议连接应用状态与实际硬件。
- **端侧 NPU 推理：** 将人物检测部署到 RK3568 RKNN 运行环境，保留模型、后处理和运行库的配套关系，而不是只在电脑上完成推理演示。
- **进程隔离与资源互斥：** Qt 通过本地接口连接语音服务和控制 worker，保留相机、串口锁及模式互斥，避免多个入口争抢设备。
- **面向失效的控制：** 检查观测时间戳、目标歧义、通信异常和停止回执；拒绝把过期检测坐标伪装成新目标继续驱动。
- **真实设备问题处理：** 统一音频到 16 kHz，处理 RK817 采样率切换后的录音锁死；适配 ConnMan Wi-Fi Agent 与系统状态展示。
- **可追溯迭代：** 使用失败图像、检测记录、假时钟／UART 回归和实机日志区分算法收益与机械效果，保留配套源码、哈希及回退基线。

## 已记录的实机结果

以 **CONT-V2** 一次正常移动测试为例：

| 指标 | 记录结果 |
| --- | ---: |
| 跟随时长 | 约 65.5 秒 |
| 最终丢失跟踪 | 0 次 |
| 短暂停 / 恢复 | 1 / 1 次 |
| 采集至检测结果延迟 | 中位 144 ms，P95 230 ms |

该测试未覆盖快速移动或长期运行；检测结果延迟不等于完整机械响应时间，也不代表识别准确率。人脸、海报和衣物误检仍可能出现，当前没有宣称完成人物身份认证或通用重识别。

这份已完成 Qt5 ARM64 构建和隔离实测的配套源码保存在 [CONT-V2 检查点](releases/2026-10-20-cont-v2/README.md)。它是可复现的阶段基线，不是开箱即用固件，也不代表板端正式入口已经切换。
